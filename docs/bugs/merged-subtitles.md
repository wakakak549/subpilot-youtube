# 单条字幕显示整段译文

2026-10-15，修复版本 `0.1.6`。

在版本 4 的译文缓存和模型日志中发现了同一段异常文本。模型为 `hy-mt2-7b`，每批 20 条、预取 120 秒；单条缓存包含从“主要目标”到“补给线被切断”的整个段落。公开的回归数据只保留复现所需的字幕与响应，省略本机路径、扩展实例标识和缓存键。

LM Studio 日志中的响应将整个段落放在一个 `[34]` 编号之后，结束原因为 `stop`。因此长段落已存在于模型返回中，播放器当时展示的是一条被污染的译文；插件的解析和缓存校验未阻止它进入显示。日志没有保存对应请求正文，不能据此还原该次完整输入。

截图上方原文为：

> main goal. If indeed an SCV is not going to be leading the Reaper, there's a

原始响应及截图原文保存在 `tests/fixtures/hy-merged-paragraph.json`。旧解析器会把该响应判断为成功，新版会拒收并重译。

真实模型实测还复现了另一条路径：20 条输入返回 18 个编号，模型先合并前三条，再把后续译文编号整体前移。只保留已返回的编号会继续产生错位，即便这些译文本身没有异常长度。该真实返回与构造的输入保存在 `tests/fixtures/hy-shifted-numbering.json`，测试要求整批拒收；这些构造的后续英文不是从使用者视频恢复的字幕。

修复包括：

- Hy-MT2 请求只发送本批待翻译条目，去掉额外上下文。
- 编号、条数不完整时整批逐条重译；无编号的短缺响应不按位置猜测。
- 结合中日韩文字与其他文字的长度权重，拦截明显膨胀的单条译文；不以截短内容代替校验。
- 解析、缓存读取、缓存写入及页面接收时检查长度；多个字幕编号不能隐藏在单条结果里。
- 缓存版本升为 5，旧版本译文不再复用，API 配置保留。
- 请求预算允许 100 条异常批次全部逐条恢复，同时保留每条最多 3 次尝试与整批请求上限。

长度检查是对明显异常的检测，不能保证模型的语义质量。格式完整但语义错译仍需要模型质量评估。

回归覆盖真实截图段落、真实模型重排编号、无编号合并、缓存重复命中、100 条逐条恢复，以及浏览器中异常内容从未进入覆盖层或缓存。验收说明见 [verification.md](../verification.md)；本地运行测试生成的 `artifacts/` 诊断文件不随源码发布。
